# P-SUMMARY v2.0.0（主持人总结）

- 实现：`packages/agent/src/prompts/summary.ts`
- 输出：**纯文本三段** → `parseSummaryText` → `normalizeSummary` / `buildFallbackSummary`
- 参数：`deepseek-flash` / **thinking 开启** / text / temperature 0.5 / max 500 tokens / 超时 **90s**
- 对应：AR-08；FR-10（自然语言、不显示 JSON）；契约 §1.4（`isFallback`）

## v2 变更

| 项 | v1 | v2 |
| --- | --- | --- |
| 未解决内容 | 让模型自己总结"还悬着什么" | **注入 `acceptedUnresolved` 清单**，第 3 段必须点到 1–2 条 |
| 到安全上限 | 无特殊处理 | 追加"讨论跑到 36 轮才收，说明还有没聊完的线头"的提示 |
| thinking / 超时 | off / 25s | **enabled / 90s** |

为什么必须显式喂"仍未解决"：深度讨论改版后，**允许带着旧分歧收束**（这是设计，不是 bug）。
如果不在 prompt 里点名，模型很容易用"总体上都认为"糊过去，而"没解决"恰恰是用户最想带走的信息。

## System（原文）

```text
你是这场圆桌的主持人，讨论已经结束，你要给观众一段总结。
你的总结要让人**不读全文也能拿走结论**，但绝不能编造讨论里没有的东西。

# 硬性要求
（全局 5 条）
5. 只写自然语言段落，不写 JSON、不写字段名、不用列表符号、不用小标题。
6. 不要在总结里出现新的主张或新的数据。
```

## User 结构

```text
# 议题
{topic}

# 讨论规模
共 {turnCount} 条发言，{人数} 位参与者。

{争论结构 debateMap + 收敛度}
{参会者 / 现场 / 统计 / 共识分歧}

# 已经确认的共识 / 分歧 / 待验证（总结只能以此为准）
{insights}

# 仍未解决（第 3 段必须点到其中 1–2 条，不要含糊带过）
- 「再培训成本该谁承担」由许澜提出，陈默未正面回答
- 分歧在于这是压缩还是重构

# 注意
讨论跑到了安全上限才收，说明还有没聊完的线头——第 3 段要明确说出“哪些问题没被解决”。

# 你刚才的收尾发言（不要整句重复）
{closingLine}

# 写作要求
1. 写成 3 段，段与段之间空一行：
   - 第 1 段：这场在哪些点上形成了共识（没有就直接说“这场没有形成明确共识”）；
   - 第 2 段：主要分歧是什么，双方各是什么主张（写出争的是什么）；
   - 第 3 段：还有什么没解决（有清单时至少点 1–2 条），以及一个可以带走的判断。
2. 总长 180–320 字；每段 1–3 句。
3. 语气像主持人在收尾，可以有一句态度，但不要煽情。
4. 不逐个人复述，不写“某某说……某某又说……”。
5. 不出现 JSON 字段名、大括号、编号列表。
6. 某类为空就明确说为空。
```

## 校验（`normalizeSummary` / `parseSummaryText`）

| 检查 | 阈值 | 处理 |
| --- | --- | --- |
| JSON 痕迹 | `{}`、`"insights":`、`"content":`、`evidenceMessageIds` | 抛 `AgentParseError`，触发重试或模板兜底 |
| 段数 | 2–4 段（目标 3） | 1 段记 `too_few_paragraphs` |
| 长度 | 20–400 字（目标 180–320） | 超长按段截断；过短记 `too_short` |

## 兜底（`buildFallbackSummary`，`isFallback=true`）

总结超时/两次失败/JSON 泄漏时，用**既有 insights 重排**成三段，不新增任何主张：

```text
这场里，几位在一个点上收拢了：{consensus}。这一点上没有出现明显的反对。
（没有共识：这场没有形成明确共识，几位更多是从各自角度补充，各说各的部分。）

没有谈拢的是：{divergence}。
（没有分歧：讨论中没有出现正面冲突，更多是侧重点不同。）

还悬着的是：{open}。如果要带走一句话：这场讨论没有给出标准答案，但把分歧的位置标出来了。
```
