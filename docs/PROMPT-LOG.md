## 1. 【工作模式 / 需求阶段】四角色分工与产品经理定位

**我下发的原始 Prompt**

```text
D:\AI开发\ai-panel-studio\docs\笔记.md
以上是我在从用户方面的提取的关键信息，算是对1.2和1.3的归纳。
我现在要求你分配产品经理，前端，后端，测试这四个角色进行开发。你是产品经理，剩下几个角色都各自开一个智能体来充当。
先说产品经理的定位：核心枢纽。其核心任务：1：先是将我们的产品的需求清单，功能定义以及关键技术要求等重点统计并从全局以及工作流程SOP的角度组织起来，找准各自的位置，然后全部以PRD或者纲要的形式落下，其为所有角色共同的北极星。
2：维护产品北极星，并在变更时及时通知各方，维护上下文。
3：确立工作流，然后分派任务，根据各个角色的任务特点进行提示词专门撰写优化和分派，确保各个角色的最终工作能够和谐而不会冲突。

前端：负责产品的前端部分，专注于前端部分的开发和对应的小开发周期内的基础测试，确保UI视觉效果的完整和BUG率的低水平。
后端：负责产品的后端部分，专注于后端部分的开发和对应的小开发周期内的基础测试，确保后端功能链路通常以及逻辑正确。
测试：负责从功能，模拟用户使用链路，压力测试，前后端畅通等角度对产品进行测试，确保每次发版前的产品功能完好，bug率低。

你先将我的话理解一遍，然后跟我同步
```

**我当时在引导什么**：这条 Prompt 的重点不是“分四个角色”，而是先定工作模式——主 Agent 以产品经理身份工作，负责 PRD、北极星、工作流和角色提示词；前后端/测试各自有明确边界；并且要求“先理解、再同步”，不允许直接跳进写代码。

**执行结果**：主 Agent 先复述了角色边界，产出 PRD 初稿、角色 SOP 和工作流；我确认后进入 G1。PM 在这里是我派出的执行角色，不是叙述者。

**产出**：`PRD.md`、`02-角色与协作SOP.md`、`WORKFLOW.md`、`TASKS.md`

## 2. 【角色补全 / Agent 阶段】发现缺少 Agent 角色

（A 指上一轮我对角色分工与 PRD 方案的确认。）

**我下发的原始 Prompt**

```text
确认A，这步之后我认为前面我们漏了一个角色，就是专门负责AGENT的部分，包括届时的提示词设计，上下文工程等，我目前认为不该将它们分散在前后端中，应该统一管理，这个任务如果再由产品经理做，那么任务太重，我认为应该单独设立一个角色专门管理，你评判一下
```

**我当时在引导什么**：我没有直接命令“再加一个 Agent 角色”，而是先指出问题——prompt 设计和上下文工程如果分散在前端/后端，会出现多套不一致的 Agent 理解；再由 AI 评判是否应该独立设角色。AI 评估后同意：产品经理兼顾这些任务过重，而且缺少独立的第二双眼睛，于是新增 AI/Agent 工程师角色。

**执行结果**：AI/Agent 角色拥有 `packages/agent`，负责五类 runtime prompt、context、policy、eval；产品经理只审行为结果和 eval，不再兼写所有 prompt。我的引导方式从“分派任务”推进到“发现结构缺口，让 AI 先评判，再决定组织调整”。

**产出**：`AGENT-BEHAVIOR.md`、`packages/agent/**`、`docs/prompts/runtime/` 五份全文、`evals/`

## 7. 【迭代阶段】从“演角色”到“真争论”，从“轮数”到“观点饱和”

**我下发的修改要求（节选）**

```text
目前，开启一次讨论后，没有返回大厅的按钮。专家状态小窗未显示 agent 运行状态。
各个专家的思考深度都不够，需要开启思考模式。
我认为 AI/AGENT 的提示词和上下文需要深度设计，目前的 AI 讨论，并没有体现出观点的碰撞，
每个专家时常是沿着自己的角色定义走，其目标不是讨论，不是观点碰撞，而是扮演好自己的角色，
这违背了讨论的初衷。同时，讨论轮数也不该硬设置为 12 轮，我认为应该设计为至多 36 轮。
目前的主持人更像是机械操控讨论流程，思考深度不够。
```

```text
讨论的结束与否应该从观点出发，而不是靠轮数看，我给的轮数只是保底而已。
```

**我当时在引导什么**：我不是加一句“请深刻一点”，而是重写 Agent 行为协议：把“角色扮演”改成“回应具体论点”，把“轮数目标”改成“争点饱和”。第一版仍用 `plannedTurns` 软目标驱动结束，我要求改为 `coverageFloor` 只做保底、`maxTurns=36` 只做安全上限，真正收束由 `saturation.ready` 决定。

**产出**：`docs/09-深度讨论与圆桌UI改版.md`、`packages/agent/src/context/debate-map.ts`、P-SPEECH/P-DECIDE v2、`RoundTable.tsx`、三套主题、`docs/prompts/devlog/02-deep-debate-rework.md`

## 附：我引导 AI 的四个动作

| 场景 | 我的动作 | 项目证据 |
| --- | --- | --- |
| 从零开始 | 先定工作模式：主 Agent 做产品经理，前后端/测试各开智能体；先理解再同步 | 本文 §1 |
| 发现结构缺口 | 不直接下命令，先指出 prompt/context 分散的问题，让 AI 评判是否独立设角色 | 本文 §2 |
| 契约与实现 | 给目标、输入、目录边界、验收标准；不达标就返工 | §3、§5 |
| 真实问题 | 给失败现象、截图、URL、可测标准，让 AI 定位并补回归 | §6、§7 |

这四步构成了我的引导方式：**定工作模式 → 发现缺口 → 用契约约束 → 用证据验收**。PM 是我派出的角色，不是我本人；我始终保留目标、确认和验收权。
